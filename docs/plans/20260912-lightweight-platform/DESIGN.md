# Technical design and research decisions

## 1. Constraints and invariants

Work from the frozen reviewed source `080ba93`. The new branch is an incremental successor, not a replacement of Mann's handoff. Keep Test identity, preference/keychain domains, project registry, application paths, recovery roots and logs separate from normal Iris. Runtime model credentials never enter research artifacts, telemetry or mobile manifests. Do not run terminal `xcodebuild`; native build and app acceptance use the existing Xcode GUI workflow. Headless `swiftc`/Swift package checks remain appropriate for isolated logic.

The global efficiency rule is to avoid work before trying to make work cheaper. Reuse verified source objects, accepted artifacts and stable context. Apply bounded retention to owned regenerable payloads. Use cheap local observation before model vision. A budget may stop work safely, but the user needs a useful recovery action and the result must remain incomplete. Token, dollar, time, storage and user-action measurements have different units and must not be substituted for one another.

## 2. Source-aware installation

### Current cause

Kneecap's source guard probes origin and `git status --porcelain` before a pinned checkout. `/Users/akrit/kneecap` was already at `fc48ba487a1e0d0cd10b30d6600acd2895ffdbed` but has a changed `bun.lock` and untracked Finder metadata. The lockfile can affect dependencies, so calling it harmless or ignoring all dirty state would be wrong. A correct directory can still be unsuitable for an automated checkout. The bug in the product is the missing safe continuation and workspace propagation, not evidence that the folder is absent.

### Minimal implementation

Extend the existing source-refusal diagnosis with a typed setup offer. Keep the original refusal classifier restricted to the verified command shape and completed working directory. Introduce a source preparation service with an injected command executor, not another general install orchestrator. Resolve `origin + commit + canonical path + Git common directory` from fresh read-only probes. Normalize only equivalent supported HTTPS/SSH origin forms; reject surprising hosts, control characters, flags and unsupported schemes.

For a dirty matching repository that already contains the required commit, prefer `git worktree add --detach <new owned path> <commit>` to copying dependencies or recloning objects. [Git worktree](https://git-scm.com/docs/git-worktree) provides a separate index and working directory with shared objects. It changes Git worktree administrative metadata, but does not reset/stash/checkout the user's worktree. Record that distinction accurately. Do not use `--force`, `-B`, `reset`, `clean`, or automatic stash. If origin/ref validation or worktree support fails, retain the original and show the exact reason. A missing commit may use the existing consented, pinned HTTPS fetch path; do not turn this phase into an unbounded network clone fallback.

The staged result must contain `runID, guideID/revision, projectID, canonical original/staged paths, expected origin/commit, observed HEAD, ownership marker, status`. Persist only in Test-owned setup state. Prefer extending existing session persistence; a separate broad state machine/store needs Terra justification. Use a unique child under the Test Projects root. Check symlink containment and destination nonexistence before creation; after staging re-probe identity and clean state. Write the registration atomically only after validation. An interrupted staging directory is not installed. Resume requires matching ownership, guide revision and source identity. Stop terminates the owned process group and leaves truthful recoverable state.

All subsequent commands and checks must use the selected staged workspace through an explicit binding. Add a versioned step field `workspace: { kind: "prepared-project", relativePath: "apps/mobile" }`; `.` explicitly names its root. Reject empty, absolute, traversal and symlinked paths. Resolve only against the validated guide/revision/project/origin/commit binding and pass that directory directly to the existing runner. Never replace arbitrary substrings in shell scripts or rewrite untrusted guide code. Legacy hard-coded commands remain blocked until the guide is republished with a structural workspace contract; explain this and never advertise a successful install. Test command access stays scoped to registered projects and known guide operations; the global marketplace execution guard stays intact.

The catalog already has a five-minute cache and bounded refresh. Add a visible refresh action and last successful refresh/failure state using the existing service. Do not poll on every render. Preserve last known inventory and icons on temporary failure. Icons retain current HTTPS, type, byte and concurrency limits. Bundle identity missing means unknown, not absent. The phone setup ending must distinguish built, installed, launched and usable, and show the real next device action.

## 3. Spatial guidance as a fresh observation

Keep the existing ladder: authored AX target first, bounded accessible tree search, then one bounded visual fallback for an eligible inferred target. Do not add a heavyweight vision framework. [Microsoft UFO](https://github.com/microsoft/UFO/blob/main/documents/docs/ufo2/overview.md) is useful prior art for structured UI plus visual grounding; it is not a drop-in macOS dependency.

The target result must carry evidence, not only `CGRect`. Add a small observation value with frontmost PID and bundle, window identity/title fingerprint, monotonic observation time, display ID/topology, coordinate-space metadata and semantic target role/identifier/label/ancestry. Keep raw window titles, URLs, screenshots and AX payloads ephemeral. Fingerprints belong to the current session and must not become activity tracking. Do not fabricate a stable element ID where AX provides none. Such targets need fresh re-resolution and an ambiguity result.

Revalidate immediately before showing guidance. PID, window, tab/document state, target role or identity changes invalidate the result even if its rectangle is identical. A moved equivalent element can be reacquired. Duplicate high-scoring controls require context or an ambiguous result. If a browser does not expose its tab state, acquire a fresh bounded observation instead of claiming the old target remains valid. Budget exhaustion means temporarily unavailable; it is not permission to display a stale highlight.

Centralize coordinate transforms for AX global top-left points, AppKit points, capture pixels and crop origin. Use the actual display topology, scale and menu-bar display transform, not an assumed first screen or universal Retina factor. [Apple AX position](https://developer.apple.com/documentation/applicationservices/kaxpositionattribute), [CGDisplayBounds](https://developer.apple.com/documentation/coregraphics/cgdisplaybounds%28_%3A%29), and [NSScreen frame](https://developer.apple.com/documentation/appkit/nsscreen/frame) define the relevant spaces. A changed topology invalidates the capture.

Show a click-through outline of the resolved control with the existing eye and short instruction. Preserve keyboard focus and Reduce Motion. Clear on app/tab changes, close, cancel, timeout and sensitive steps. Never turn a highlight into a click. Invalid, off-screen, zero-size or enormous bounds are unavailable. A whole-window target must be identified as a window, not presented as a specific button.

## 4. Versions, reusable candidates and bounded storage

The current store protects recovery and applies a 2 GiB logical backup admission cap. Successful installed versions still accumulate. Keep that cap as an admission check, but add a clear retention model so users do not eventually hit a permanent update stop. Do not introduce a second updater; [Sparkle](https://github.com/sparkle-project/Sparkle) is reference for signed update identity, not a required dependency.

Add one minimal `AcceptedCandidateRecord` under the existing Test receipt-store ownership and lock. `PendingEditCandidateIdentity` is a dirty staged pre-commit identity, so it cannot represent this accepted clean source/artifact. The new record contains current registry identity, source base/edit commits and change ID, artifact digest, verification/review receipt identities and status. It contains no prompt, source tree or user data. Adapt the existing saved-change/delivery machinery, without adding another coordinator. Recheck and deliver must verify those identities at invocation and before swap. A stale receipt or model's success prose cannot establish acceptance. Rechecking a stored candidate must make zero planner/editor/repair generation calls. If a new independent review is required, surface that separately and count it.

Distinguish `installed` from `UI accepted`. A named observed user journey marks UI acceptance; a build cannot. Persist current and preceding UI-accepted receipt IDs per Test project/bundle under the same store lock. Derive a pure retention plan from those durable links. Protect current app, newest working rollback, previously known-good rollback until the replacement is accepted, prepared/in-flight/Undo/recovery/pinned references, and any overlapping/shared path. Legacy receipts without enough identity remain protected. Only complete, unreferenced, superseded or restored payloads become eligible. Preserve slim records after payload removal and show that older full Undo is unavailable.

Preview eligible bytes and protected versions. Extend the existing explicit Test cleanup action first. On budget pressure, offer cleanup or cancel before changing the installed app. No silent cleanup of user projects, source clones, caches or normal app data. Later automatic cleanup can reuse the same classifier only after repeated lifecycle evidence; it is not a new background daemon in this phase. Deletion is per verified payload, with truthful partial-failure reporting, not a promise of an atomic multi-file unlink transaction. Revalidate path/identity/references under the same ownership lock at deletion and admission. Test interruption and race injection.

Record logical referenced bytes, allocated payload bytes and observed filesystem free-space change separately. Hardlinks and APFS clones make these non-equivalent. Keep at most the configured managed payload budget while protecting recovery; if protected payloads alone exceed budget, state this and refuse further backup admission without deleting them. Notes, media and user-created files remain outside app Undo.

## 5. Smart routing and the complex-feature harness

Development-agent routing and Iris runtime routing are separate controls. Use Luna Medium for bounded implementation, Luna High for nontrivial edge cases and Terra High for review or demonstrated escalation. Root owns product scope and integration choices. Do not spend an extra model call merely to classify every simple action.

Runtime routes must honor transport and capability. General Ask/screen help currently uses Anthropic Messages through funded or BYO modes; Codex powers editing. A Codex model selection cannot replace a forced-tool or image transport it does not implement. Select from verified available models and preserve explicit user selection. Provider-reported model is separate from requested model, especially when a funded endpoint overrides client choice. An unavailable model/auth/permission error needs a precise next action rather than a canned conversational fallback.

The next harness correction targets missing requirement context and retained noise before another broad model comparison. `FeatureEditRepositoryContext` must include bounded relevant consumers as well as imports. Respect file/symlink/byte limits. Diagnostic selection must use actual command result and bounded failure evidence, not any source text containing `false` or `error`. Preserve the user's constraints and the smallest useful failure summary across repair. Reserve independent review capacity; never spend it repeatedly editing the same failure. Re-run a costly candidate only after classifying the failure and making a relevant correction.

Extend the current ledger with a payload-free outcome row: run/candidate identity, requested/observed route and effort, stage, physical attempt, retry class, admitted bytes, supplied token categories, elapsed time, checks, delivery and UI outcome. Count every physical call once, including cancellation or uncertain settlement. Missing usage or price is unknown. For OpenAI, cached tokens are a subset of input and reasoning tokens a subset of output; do not double-count them. Anthropic cache-creation/cache-read fields require their own provider normalization. [OpenAI reasoning usage](https://developers.openai.com/api/docs/guides/reasoning) confirms reasoning is billed output, so higher effort must be assessed by total successful outcome cost, not assumed free.

Starting control: one intake/plan, no more than two edit/repair attempts, code-admission review and final behavior review within existing hard call/byte/deadline limits. This is a ceiling, not a mandate to use every stage or replace existing stricter limits. Report cost per accepted result and failed-run spend, retries and latency. Do not claim statistically stable p95 or model superiority from a handful of runs. First use offline replay and one frozen live complex case. Expand a route comparison only if that result resolves a decision, with actual pricing verified at run time.

## 6. Mobile install hub, not another Kneecap runtime

Kneecap already has Capacitor 8, Vite/DOM/WASM assets and app-local native media plugins. Start by improving distribution and install discovery. The smallest new component is a phone-sized web install hub backed by a validated catalog route manifest. It lists supported apps, device compatibility, Open/Install/Setup needed, and concise progress/recovery instructions. No dependency is required beyond a small static module and stylesheet for the first prototype. It can be served locally for browser acceptance before deployment. Do not invent live TestFlight, App Store, APK or web-editor URLs.

Manifest contract: version, app/project ID, title, icon, route kind (`web`, `app-store`, `testflight`, `android-package`, `mac-assisted`, `unavailable`), supported OS, verified HTTPS destination or absent, evidence/status, optional runtime/capabilities, download size when known, and publisher setup instructions. Validation rejects malformed/duplicate identities, arbitrary schemes, credentials in URLs, unknown executable destinations and unsupported native claims. Device detection suggests routes but a user can select a different device. Missing signing/distribution is a clear setup state, never a successful install button. Track no personal usage in this prototype.

For iPhone, the simplest beta path is a publisher-built signed Kneecap binary through TestFlight, so testers do not install Xcode. Developer enrollment, signing, upload and physical-device acceptance remain separate work with real prerequisites. A browser hub cannot install unsigned native software. [Apple TestFlight](https://developer.apple.com/testflight/) and [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) apply. The HTML5/JS mini-app allowance in guideline 4.7 is conditional and does not authorize a general downloaded native-code host. A later native hub may embed reviewed web experiences; never hand arbitrary catalog content Kneecap's native bridge. Do not build a remote shell, new signing service or second single-app Capacitor wrapper now.

For Android, a verified published APK may be handed to the system installer, which preserves signing identity and normal user authorization. [PackageInstaller](https://developer.android.com/reference/android/content/pm/PackageInstaller) is a later native adapter, not necessary to build the initial route hub. Region/platform distribution rules must be checked again at release.

Cache only small catalog metadata in the initial hub with a bounded age and visible refresh. Do not prefetch binaries, media or AI weights. Offline means last verified catalog plus unavailable network actions. A later PWA/native cache needs explicit size/retention and update compatibility; do not introduce a service-worker cache that silently retains every release.

## 7. Development context and integration

Three inherited AGENTS files contain 115,517 bytes and 16,407 words, mostly accumulated historical prose. Archive the exact originals under on-demand history, hash them, and replace active files with compact current invariants and links. Preserve every operative permission, identity, source, cancellation, UI and evidence boundary. Terra reviews an invariant mapping. Measure bytes/words only; this is not proof of runtime token savings.

Merge by dependency: compact active rules, standalone source/spatial/hub contracts, corresponding UI/service wiring, candidate identity, retention, routing/context/outcome wiring, then a combined native build. Installer and spatial integrate through the same guide revision/workspace context; neither owns the other's source file without an explicit handoff. Candidate identity precedes cleanup of successful versions. Runtime route changes wait for provider/capability checks. One desktop owner records screenshots and exact app identity during UI tests; others use headless or isolated browser sessions.

Any claimed completion includes the source revision, exact command/test result, installed artifact identity if applicable, observed user steps, measurements, and remaining uncertainty. A hardware/auth/signing blocker pauses that acceptance lane while implementation and independent tests continue elsewhere.
