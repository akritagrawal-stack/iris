The low-friction contract should be a new `ProjectStager` behind a narrow interface:

```text
resolve(sourcePath, expectedOrigin, expectedCommit) -> SourceIdentity | dirtyRefusal | unknown
stage(SourceIdentity, destination) -> StagedProject
cancel(StagedProject) -> recoverable staged state
```

The UI offers two explicit choices after catalog selection:

1. **Use this existing checkout.** Freshly read origin, HEAD, and porcelain. Continue only when origin and the expected commit match and status is empty.
2. **Make an isolated copy.** Copy or clone into a fresh Test-owned directory below the registry root, then re-probe origin, HEAD, status, symlink containment, and the expected build path. Never modify the selected checkout. Preserve all user copies, including dirty ones. A dirty result says exactly which literal folder was refused and offers “Review it yourself, then Try again” or the isolated-copy choice.

Staging should be atomic and resumable: write to a unique temporary child, verify the copy, then rename into a record containing UUID, original path, staged path, origin, commit, bundle ID, app path, artifact path, and cleanup policy. ## Spatial guidance: current pipeline and root cause

The existing ladder is sound in principle. `IrisGuideModels.swift:192-273` stores a text descriptor, optional app bundle ID, and window flag. `GuidePointing.swift:19-89, 177-287` distinguishes authored AX targets, shell windows, and inferred model targets; sensitive steps, wrong foreground app, missing Screen Recording, and no-target cases have separate refusals. `GuideStepPointing.swift:375-490` resolves focused window, AX tree, then model only for an inferred target. It captures frontmost app, display frames, and window before the model ask and rejects the result if freshness fails. `GuideSessionController.swift:604-821` coalesces requests, budgets four model asks per step, and generation-guards late results.

The root cause is semantic identity loss after lookup. `GuideStepPointing.swift:493-765` walks AX with a depth-16, 6,000-node, 0.4-second bound and scores label/context, but returns only a rectangle. `GuidePointing.swift:93-175` makes eye-flight identity step ID, point, and label, and `GuideEyeFlightMemo` treats positions within one point as the same answer. `GuidePointingFreshness.swift:4-57` checks app, display frames, finite geometry, and window movement/resize. Those checks catch stale geometry, but not a changed browser tab, a duplicate label, a replaced AX element, a new process with the same bundle ID, or a changed window state. The model path in `CompanionManager.swift:2613-2807` asks for image-space `[POINT:x,y:label]`, maps pixels to a display, and uses a fixed 44-point square. It has no durable element identity and no rendered target rectangle beyond the eye destination. Geometry work alone can therefore point at the wrong control while all current freshness checks pass.

The spatial edit set is `GuideStepPointing.swift` (`GuideTargetLocating`, `resolve`, and AX frame conversion) to return `ObservationSnapshot` and `TargetFingerprint`; `CompanionScreenCaptureUtility.swift` to carry display ID, pixel, point, crop, and scale metadata; `CompanionManager.swift` to attach model points to that snapshot; `GuideSessionController.swift` (`refreshPointingForTheOpenStep`) to reacquire and invalidate context; and `OverlayWindow.swift` plus the eye sender to render a click-through target rectangle. Add pure mapper/fingerprint tests beside `SpatialGuidanceChecks.swift` and existing pointing tests.

Use an immutable observation contract:

```text
ObservationSnapshot {
  id, monotonicTime, frontmostPID, bundleID, windowAXIdentity,
  windowTitleHash, tabOrURLHost, AXRole, normalizedLabel, AXAncestry,
  targetFrame, displayID, CGDisplayBounds, NSScreen frame/visibleFrame,
  imagePixelSize, logicalPointSize, backingScale, screenDigest
}
TargetFingerprint = PID + bundle + window identity + AX role/label/ancestry
                   + display ID + display topology/scale + capture digest
```

The flow is: fresh foreground and AX observation; rank semantic candidates; capture display metadata; resolve the frame; for an inferred target only, ask the model with that metadata; immediately reacquire the same AX fingerprint and foreground/tab/window state; then render a click-through highlight rectangle plus the eye. A highlight is feedback, never an implicit click. If the element moved but its AX identity remains, update the rectangle. If the tab, process, role, ancestry, or required state changed, clear the highlight and reobserve. Pass `TargetContext` into follow-up chat turns; never reuse a prior rectangle after interruption or user navigation.

Confidence is explicit: authored AX match high, shell window high/medium, model inference tentative. Missing AX permission, missing Screen Recording, ambiguous duplicate candidates, minimized/off-screen target, stale capture, or an unavailable transform yields `unknown` with a user-facing next step. It must not become “no target” or success. A step with no visual target remains quiet. A sensitive step never captures.

Coordinate conversion must be centralized. Apple defines `kAXPositionAttribute` as the global top-left position relative to the display with the menu bar ([AXPositionAttribute](https://developer.apple.com/documentation/applicationservices/kaxpositionattribute)); `CGDisplayBounds` supplies global display bounds ([CGDisplayBounds](https://developer.apple.com/documentation/coregraphics/cgdisplaybounds%28_%3A%29)); AppKit uses bottom-left screen coordinates for window frames ([NSWindow.frame](https://developer.apple.com/documentation/appkit/nswindow/frame)). `NSScreen.frame` includes menu bar and Dock while `visibleFrame` is usable and can change ([frame](https://developer.apple.com/documentation/appkit/nsscreen/frame), [visibleFrame](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe)). ScreenCaptureKit capture rectangles are in display-space points ([SCScreenshotManager captureImage](https://developer.apple.com/documentation/screencapturekit/scscreenshotmanager/captureimage%28in%3Acompletionhandler%3A%29)). Replace the brittle `NSScreen.screens.first?.frame.maxY` conversion with a display-ID/topology transform carrying pixel dimensions, logical points, and per-display scale. This handles negative origins, displays above or below, Retina, crop, and changed visible areas.

Apple’s AX APIs are best treated as fallible observations: create the app element by PID ([AXUIElementCreateApplication](https://developer.apple.com/documentation/applicationservices/1459374-axuielementcreateapplication)), read attributes with `AXUIElementCopyAttributeValue` ([API](https://developer.apple.com/documentation/applicationservices/1462085-axuielementcopyattributevalue)), decode typed geometry with `AXValueGetValue` ([API](https://developer.apple.com/documentation/applicationservices/1462933-axvaluegetvalue)), and check trust ([AXIsProcessTrusted](https://developer.apple.com/documentation/applicationservices/1460720-axisprocesstrusted)). Refresh frontmost state immediately before dispatch ([NSWorkspace.frontmostApplication](https://developer.apple.com/documentation/appkit/nsworkspace/frontmostapplication)).

## Architecture comparisons and tests

Three open-source designs support this direction. [Munim Computer Use](https://github.com/munimtechnologies/munim-computer-use) prefers accessibility-tree stable IDs over coordinates, carries screen origin and pixels-per-point with every capture, and uses “look, act, verify.” [OpenSymph open-computer-use](https://github.com/opensymph/open-computer-use) exposes accessibility state plus screenshots, prefers semantic element indices, shows a visible cursor, and gates focus and sensitive actions. [Microsoft Open-Kosmos](https://github.com/microsoft/open-kosmos/blob/main/docs/computer-use-tech-doc.md) separates capture/input into one manager, refreshes foreground state before allowlist-sensitive dispatch, and maps coordinates from display ID, origin, and scale. The common rule is to bind an action to the observation that produced it and verify after it.

Tests should catch semantic mistakes, not only math: coordinate mapper cases for Retina, mixed scale, negative secondary origins, displays above/below, crops, invalid display IDs, and changed topology; fingerprint cases for same rectangle with a different role/tab/PID, moved same AX element, duplicate labels, and replacement windows; integration with a fake AX tree and capture where the exact authored control beats a header duplicate, a tab switch rejects the model point, a minimized/disappeared control clears the highlight, and a moved window is re-found by identity. Follow-up tests must invalidate context after user navigation, interruption, guide close, or monitor change. Installer tests should cover exact dirty-guard classification, origin/commit mismatch, atomic staging, cancellation and restart, retained staged copy, catalog forced refresh/stale error, bounded icon fallback, and proof that Test registry discovery never sees normal installed apps.
